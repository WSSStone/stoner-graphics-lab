# Lab Session, Submission and Runtime Limits

## Session state

`FInteractiveLabSession` is an Application coordinator over independent camera, input, UI, settings and preset services. Demo selects the strict-cooked root, realizes content through Renderer and supplies backend-neutral presentation bindings. State is Starting -> Ready -> Running, with PausedZeroExtent, TransitionPending, Draining, Failed and Closed. UI failure may set UIUnavailable while a valid scene continues; native failure preserves its first cause and follows the bounded shutdown policy below, distinguishing compatibility cleanup from proven retirement.

`FLabSettingsSnapshot` contains camera revision, manual exposure, SDR tone-map selection, HDR viewing version, requested/effective output profiles, debug bypass, UI visibility/brightness, resolved white and display generation. Keep separate remembered SDR/HDR selections; choosing HDR does not reuse an SDR tone-map identity. Existing exposure bounds are [-16,+16] stops. Validate all fields before one revision is committed.

At most one active and one pending output request exist. The newest valid request replaces pending intent. Invalid requests report a reason and do not replace valid pending/effective state. Drain incompatible frame ownership before rebuilding targets; resolve capabilities again using the latest display generation. If the former output is no longer valid, select explicit SDR fallback or pause if none exists. Completion publishes exactly one coherent effective snapshot. UI reports Requested, Pending, Effective and Failed separately.

## RHI and Renderer asynchronous seam

Add proposed `IRHICommandQueue::SubmitDeferred` with the existing Submit arguments and a mandatory non-null completion fence. Success means accepted/queued, not completed or displayed. A null completion fence is rejected with InvalidState. With a non-null fence, the base/default implementation returns Unsupported without submitting; it must never silently invoke a synchronous Submit. A declared deferred-submission capability gates native lab startup. Required Vulkan/Metal implementations support it; deterministic tests may signal immediately but are labeled deterministic.

Existing `Submit` and the formal `SubmitAndWait` facade retain their documented caller behavior. Preview recording uses a new `FOutputTransformExecutor::SubmitPreview`/poll/retire path that does not call the existing unconditional WaitForCompletion. Extend graph validation with explicit `EFrameExecutionPurpose::{InteractivePreview,FormalValidation}` and readback selection; zero readbacks is valid only in preview. Formal required bindings/probe/token checks remain unchanged.

Vulkan requires a real backend change: replace per-call submission lifetime in `FVulkanNativeContext::ExecuteRecordedCommands` with bounded backend-private submission records. A record retains command pool/buffer, descriptors, resource generations, native fence/semaphores and result until completion. Poll uses native fence status; finite Wait cannot translate into an infinite native wait. Cache persistent native resource realizations by RHI identity/generation; do not rebuild/upload the scene every frame. Existing formal execution can synchronously drain its own record. Tests must prove that SubmitDeferred returns while an injected unsignaled completion remains pending.

Metal reuses completion-handler ownership and exposes the same accepted/completed distinctions. Native display commit or present-queued token is not proof of physical scanout. No backend reports a queued preview as a formal native-probe pass.

Presentation bindings borrow one acquired native drawable/image as a generation-tagged RHI texture with acquire synchronization. The Renderer graph writes the sole final output transfer directly to this imported target, then transitions it to presentation. The backend retains native ownership until presentation completion/release or the explicitly qualified terminal compatibility cleanup below; Renderer never calls graphics APIs. This direct-target path is mandatory for Vulkan, whose present recorded TextureCopy path is unsupported; do not assume that unsupported operation will execute. A future general texture-copy expansion is unnecessary for this milestone. UI scene-copy is a fullscreen draw, not an implicit native texture copy.

The additive `IRHISwapchain` seams default to Unsupported. `AcquireBorrowedTarget` may return NotReady with an empty target while a bounded native acquisition is pending; polling reuses the same frame token and slot. `PresentBorrowedTarget` takes either render-finished synchronization or a matching render lease whose completion fence can be polled without blocking. A failed render fence reports Failed, never perpetual NotReady or successful presentation. `ReleaseBorrowedTarget` permits logical cancellation before submission with a null fence; after submission it requires terminal render completion. Logical cancellation does not imply that an unpresented Vulkan image has been returned to the presentation engine. Without native image-release support, retain that acquisition against the generation budget until valid presentation or generation teardown; never silently recycle its semaphore or pretend the image was returned. Cancellation of a pending acquisition must retain its bounded admission and native owners until the acquisition task actually finishes. Resize and shutdown must account for these pending acquisitions as well as published targets and presentation leases.

Metal acquires drawables through at most two backend-private asynchronous jobs. Canceling or destroying a swapchain cancels every unpublished job, and completed canceled jobs retire even if the surface remains alive. Its native drawable callback completes the independent release lease; only a positive `presentedTime` advances the presented-frame record. Apple documents zero as not presented or dropped, so release completion alone is not display evidence ([Apple documentation](https://developer.apple.com/documentation/metal/mtldrawable/presentedtime)). Completion state retains the image and synchronization owners without retaining a drawable that owns the callback itself.

Frame states: Free -> Recording -> Submitted -> PresentationQueued -> RenderCompleted -> Retired -> Free; presentation leases have a separate lifecycle. Two slots each own command bindings, mutable parameter buffers, scene attachments, UI geometry/leases and output generation. Immutable loaded content may be shared. The render fence covers command buffers, UI texture sampling and scene resources, not presentation-engine completion. Backend image-indexed presentation leases separately retain each borrowed swapchain image and render-finished semaphore until the acquired-image dependency proves prior presentation release or an explicit presentation fence completes. Two frame slots do not imply two swapchain images/semaphores. Limit swapchain images/presentation leases to 8 per active generation; unsupported surface minima fail startup.

### Vulkan capability selection and bounded compatibility path

At device startup, inspect the selected physical device's extension list and `VkPhysicalDeviceSwapchainMaintenance1FeaturesEXT::swapchainMaintenance1` through `vkGetPhysicalDeviceFeatures2`. Record advertised support separately from enabled support. Check the [extension dependencies](https://docs.vulkan.org/refpages/latest/refpages/source/VK_EXT_swapchain_maintenance1.html): KHR_swapchain, EXT_surface_maintenance1 and either core Vulkan 1.1 or KHR_get_physical_device_properties2. Use a query entry point valid for the negotiated API/instance extensions; the existing Vulkan 1.0 initialization must not call core features2 unconditionally. An unavailable optional dependency/query mechanism selects fallback with its own reason, not an initialization error. Prefer `PresentationFence` only after enabling `VK_EXT_swapchain_maintenance1` and its feature and resolving the entry points actually used by that path. Present fences are supplied through the present-info chain; do not invent a separate present-fence entry point. Missing extension/feature selects `AcquireHistory` and permits lab startup. A failed optional enablement may retry device creation once without the optional feature before any lab resources/submissions exist; preserve the reason. Device loss or a later execution error is a failure, never an excuse to relabel a live path as fallback. Inspection/query failure is not evidence that the extension is absent: report the native error and fail initialization when a usable device cannot be established. `vulkaninfo` is supporting inventory, not an external prerequisite to implementation or startup.

Expose the selected retirement mode and reason through backend-neutral RHI capability/status values; deferred-submit support and explicit presentation-fence support remain distinct. Do not gate lab startup on `bSupportsIndependentPresentationCompletion` alone: an acquire-history implementation can provide safe steady-state reuse without an explicit close-time presentation fence. Keep native feature detection and retirement policy private to Vulkan. No additional present-wait extension, general capability framework or probe executable is required.

- **PresentationFence**: Retain image-indexed present leases until present fences complete. Drain render and presentation owners before old-generation destruction. Poll in bounded slices, keeping event handling live.
- **AcquireHistory, ordinary frames**: Keep render resources indexed by the two frame slots and render-finished semaphores indexed by swapchain image. Reacquisition of the same image plus completion of its acquire synchronization proves the prior presentation wait has finished; merely returning the image index or observing a render fence is insufficient. The CPU may poll an acquire fence for destruction, or track completion of a submission that waited on the acquire semaphore. No per-frame queue/device idle or CPU image bridge is allowed.
- **AcquireHistory, recreation**: Drain old render uses, retain the old swapchain and its unresolved present records, and create a replacement linked through `oldSwapchain`. Following the [Khronos recreation example](https://docs.vulkan.org/samples/latest/samples/api/swapchain_recreation/README.html), retire the predecessor only after the replacement's first presentation has itself been retired through reacquisition synchronization. Never infer this from merely submitting/presenting the replacement. Allow at most one active and one retiring swapchain generation (<=8 images each, <=16 total presentation/acquisition records). Check aggregate estimated color storage <=512 MiB using actual image count, extent and format bytes; this excludes opaque driver overhead and is separate from the unchanged 1 GiB slot-target budget. Free render-only old attachments after actual render completion so fallback does not retain a second full set of scene/UI targets. Coalesce requests into the existing one latest-valid pending request; do not allocate a third generation. Continue acquiring/presenting the active generation only while it is surface-compatible to make retirement progress. Otherwise pause with events serviced; after the existing 5 s transition deadline, fail and enter terminal cleanup. Zero extent pauses allocation and rendering, preserving bounded owners; resume or close resolves them. Surface loss, canceled unpresented images and replacement failure must retain unresolved owners and follow this same bounded terminal policy when progress is impossible. Creating a replacement may retire the old swapchain even if creation fails; never promise to resume acquisitions from that old handle.
- **AcquireHistory, final close**: Stop new work, finish known render/acquire uses, and use a single terminal `vkDeviceWaitIdle` compatibility cleanup before destroying remaining presentation resources. This is the common practice documented by the [Khronos guide](https://docs.vulkan.org/guide/latest/swapchain_semaphore_reuse.html), not a specification-level proof of presentation retirement. Record `shutdownAssurance=IdleAssumed`, outstanding presentation owners before cleanup, the idle result/duration and final host-owned counts. This limited assumption is accepted only for terminal lab cleanup, never ordinary reuse, resize or formal evidence. Native idle has no timeout: isolate it from the event-service thread and retain all owners while it runs. The 5 s drain deadline latches TimedOut; a 10 s shutdown watchdog bounds the entire terminal phase in both interactive and validation runs, terminating the failed process without racing native destructors if necessary. Implement this in the existing process/lifecycle infrastructure, without a new executable. Forced termination/device loss stays failed and records residual/abandoned owners; it is never successful compatibility cleanup.

A completed fallback run may satisfy a native 030 gate with its declared limitations; absence of maintenance1 alone is not Unsupported or a validation gap. `shutdownAssurance=Proven` is reserved for an actual release proof (presentation fences or Metal release callbacks), while `Forced`/`DeviceLost` are failures. A selected extension path must not use the compatibility assumption to hide an execution failure. Neither assurance value claims physical scanout. Legacy/formal paths keep their existing behavior and authority; these 030 compatibility rules do not alter their validators.

### Resource ownership and retirement

Demo's `FLabProductionFrameContext` orchestrates two frame-slot records; Renderer owns/realizes their RHI resources and enforces the corresponding leases. Backend owns native submission records and presentation leases. The two completion domains use these rules:

| Resource | Last-use / reuse condition |
| --- | --- |
| Copied UI packet and frame geometry/uniform resources | No unsubmitted recording references, and all render submissions using the slot have completed; a slot may be reused even while a separate presentation lease is pending |
| Font/widget GPU texture generation and retained CPU shadow/upload data | No prepared/queued snapshot leases and every upload/render use completed; current cached generations can remain resident within the total budget, while superseded/destroy-requested generations can retire and acknowledge destroy |
| Scene/composition attachments | Render completion permits slot reuse; Renderer may retain allocations for the next frame. Recreation drains render uses; swapchain presentation ownership retires separately under the selected mode. Terminal close follows its declared assurance |
| Borrowed output image, render-finished semaphore and native present ownership | Backend's image-indexed lease remains until proven release/presentation-fence completion, except the explicitly reported terminal AcquireHistory compatibility cleanup; render completion alone never frees these |
| Native command/descriptor/submission records | Retain each native owner until its actual render use completes; transfer presentation-owned objects to their independent lease rather than retaining UI sampling leases there |

Cancellation before submit releases only unsubmitted references. Failed or timed-out native work follows the live-reference retention rule above. Tests must independently delay render and presentation: an unsignaled render fence prevents UI generation retirement; after render completes a superseded unleased UI texture can retire while the borrowed image/present semaphore still remain owned.

## Frozen limits v1

These are chosen resource limits to implement and validate, not measured performance results. The endurance/smoke/lifecycle case selection is defined separately in [validation-evidence.md](validation-evidence.md); resource limits apply equally to every case. Byte budgets include active and retiring generations unless explicitly stated otherwise. MiB means 1,048,576 bytes.

| Resource/control | Limit | Overflow/failure behavior |
| --- | --- | --- |
| Native windows / loaded workloads | 1 / 1 | Reject extra session/window |
| Frames in flight | Exactly 2 maximum; busy slots yield event service | Never allocate a third slot |
| Drawable | Each axis <=4096; <=7,864,320 pixels; zero pauses | Reject/diagnose unsupported extent without resampling; valid later resize can recover |
| Swapchain images/presentation leases | <=8 per generation; fallback <=2 generations (1 active + 1 retiring), <=16 total records | Unsupported if native minimum exceeds 8; coalesce/pause at generation cap, fail on transition deadline |
| Fallback swapchain color storage | <=512 MiB aggregate estimated bytes; opaque driver overhead reported separately | Check actual image count/extent/format; reject over-budget replacement, never allocate a third generation |
| Slot render targets | 1 GiB aggregate across both slots and retiring targets; backend memory limit may be lower | Preflight checked byte counts and fail allocation coherently |
| Input events | 4096 per interval | Cancel/quarantine gestures; latch close/focus separately |
| Committed text | 4096 UTF-8 bytes per interval; 64 KiB per editable value/clipboard operation | Reject over-limit input as a whole, report once |
| UI vertices / indices | 262,144 / 786,432 per snapshot; 20-byte vertices, uint32 indices | Reject whole packet before GPU allocation |
| UI commands | 4096 per snapshot, including reset operations | Reject whole packet |
| Snapshot staging | 2 immutable packets (<=9 MiB each, including commands) plus one 9 MiB construction buffer | Retire before replacing; no unbounded queue |
| UI logical texture slots | 256, including font textures | Reject creation |
| UI textures | Each <=2048x2048 RGBA8; 64 MiB GPU and 64 MiB CPU shadows aggregate | Defer bounded preparation, then UIUnavailable |
| UI upload payload | 16 MiB per eligible frame, <=64 texture requests | Leave request pending within retry deadline |
| Texture generations | <=512 active/retiring records, governed also by total byte limit | Retire first; bounded retry; never evict leased data |
| Font display scale | Supported content scale [0.5,4]; raster-size cache <=16 sizes | Release unused sizes; explicit unsupported scale if unable to prepare |
| Preset | 64 KiB bytes; one pending validated preset | Reject excess/replace pending only by explicit newer import |
| Capture queue | 2 requests including active; <=1 readback completion processed/frame | New request returns Busy |
| Capture staging | 128 MiB total | Refuse allocation; never perform hidden resampling |
| Diagnostics | Ring of 256 entries, <=1024 UTF-8 bytes each; monotonic aggregate counters | Evict oldest detail, retain counts/first terminal failure |
| Texture retry | 120 eligible frames or 5 s, first reached | Disable UI with diagnostic |
| Output transition/drain/capture | 5 s each | Report TimedOut; retain valid old output only if coherent and still usable, else fail/close |
| Terminal shutdown watchdog | 10 s from close/terminal-failure entry, interactive and validation | Forced termination is failed; preserve residual-owner diagnostics, never destroy objects racing live native work |
| Event-service wait slice | <=16 ms during busy submission/transition; <=50 ms minimized | Continue polling events; no busy render/upload loop |
| Idle pending preset | One record until non-zero extent, cancel or close | No partial commit and no rendering while paused |

The current UI-enabled Deferred footprint is 64 bytes/pixel/slot excluding the borrowed final target. Two slots at 7,864,320 pixels use 960 MiB, leaving 64 MiB for bounded diagnostic targets/alignment; recreate only after old targets drain. Extra attachments must pass the same byte preflight, never silently raise limits. Counter bounds are exact; actual native memory use may include driver overhead and is measured separately. At steady state after warmup, record application-owned counts/bytes and native submission ownership; after render drain, render-transient owners return to quiescent counts. AcquireHistory may retain the bounded active generation and one retiring generation while waiting for reacquisition; record these separately rather than claiming zero presentation owners. After completed cleanup, host-owned counts reach zero; IdleAssumed does not prove native presentation retirement. Forced/device-loss exit records residual owners instead of claiming zero. Optional RSS samples retain the existing 16 MiB growth diagnostic but do not replace precise ownership assertions or claim a universal driver-memory bound.

## Preview debug selection

Existing Feature 029 diagnostic bypass construction always adds a diagnostic readback. Preview therefore separates live `BoundedVisualization` display from `NumericReadback` action: live visualization samples the chosen stage through the existing diagnostic shader into a bounded <=1024x1024 encoded-sRGB texture shown in a UI widget, with zero diagnostic readback buffers/passes. It is explicitly a diagnostic view, not a formal scene image or new HDR output transform. Register the Renderer-owned GPU target through ui-rendering.md's private registry path, retain its producer-before-sample dependency and frame generation, and bind it with the correct sampled sRGB interpretation before UI composition. Hiding UI skips this widget target/pass while retaining the debug selection; NumericReadback remains an explicit independent capture action. Selecting NumericReadback chooses the stage but creates no readback until the user invokes explicit capture. Retain mode, selected stage/domain and visualization range in preset and effective-state diagnostics using [lab-preset.md](lab-preset.md)'s complete debug object; NumericReadback maps to the existing HDRPreservingReadback identifier and never persists an active capture request; the formal bypass path keeps its existing readback requirements. Zero-capture tests include every live debug selection.

## Explicit capture and authority isolation

No capture request means zero image readback copies, mappings or readback waits in the real native path, and zero per-frame queue/device-idle calls. Fence polling for slot reuse is allowed. An explicit capture selects the next stable settings/display generation, records a request/frame token and copies only that image after appropriate ordering. Process the readback after completion; no frame-wide synchronous stall is introduced into ordinary submission. Frame equality is by token, not a nearby screenshot.

SDR capture can export bounded exact-size PNG plus JSON, labeled UI smoke or interactive preview, never Accepted. HDR interactive capture produces numeric/identity JSON and bounded ignored raw data for nonvisual diagnostics; no PNG is labeled an HDR appearance match, and no SDR conversion is added to this phase. The panel explains the HDR export's diagnostic purpose. Existing formal capture paths remain separately available and enforce frozen software/camera/settings.

## Proposed CLI additions

Retain existing `--mode interactive|validate`, backend, strict-cooked and output profile arguments. Add the following switches in `FDemoConfiguration`; commands are planned interfaces until implemented:

| Option | Behavior |
| --- | --- |
| `--interactive-lab` | Select lab behavior for native production-content Deferred runs; incompatible with calibration preview, formal visible capture and formal production-capture root |
| `--lab-vulkan-retirement auto\|acquire-history` | Default auto; acquire-history is allowed only with `--mode validate --interactive-lab --backend vulkan` and disables optional maintenance1 before device creation for fallback coverage. Never forces unsupported extension support or changes formal mode |
| `--lab-ui on\|off` | Default on in lab; off requires only scene/output closure, on requires UI closure too; enabling later preflights the same generation as defined in ui-rendering.md. UI-off remains preview unless invoking separate formal validation |
| `--lab-preset-input PATH` | Explicit bounded local preset import; exact workload revision/root/source digest checks; target/backend/cooked generation are provenance only |
| `--lab-export-root PATH` | Dedicated output directory for explicit preset/UI-smoke actions; default `Build/InteractiveLab/Exports` |
| `--lab-input-script PATH` | Bounded deterministic event/settings sequence in validate mode only |
| `--lab-report PATH` | Bounded lab JSON, distinct from formal probe/acceptance reports |

`--mode validate --interactive-lab` is a bounded non-authoritative lab test requiring positive --frames; the name validate never promotes it to formal image authority. Headless native/unit UI fixtures run through StonerTest and need no new Demo workload. Preserve existing process exit meanings: 2 configuration, 3 unavailable runtime, 4 initialization, 5 frame, 6 validation, 7 report failure.
