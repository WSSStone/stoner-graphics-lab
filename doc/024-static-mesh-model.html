024 - Static Mesh & Model Pipeline

状态：已交付 · 更新：2026-08-14 · Roadmap Phase 024 · 层级：Asset / Renderer / RHI / Vulkan

2. 本期核心摘要

本期把 glTF 2.0/GLB 静态模型导入为引擎自己的 immutable CPU Asset。一个源文件可原子地产出 Mesh、Model、Material、Image 与 Texture typed subresources；几何在发布前完成 accessor 解码、Unreal 风格坐标转换、法线/切线补全、bounds 与依赖验证，Renderer 再把 typed mesh 显式打包为 RHI vertex/index buffers。

学习价值集中在“authoring data 不等于 GPU data”。Asset 保存可验证、可重煮、与 API 无关的语义数组和层级；Renderer 决定 interleaving、index width 与 upload；RHI 描述 portable transfer；Vulkan 执行真实 allocation/copy/readback。这个分层让后续 Meshlet、Ray Tracing 和其他 backend 能复用同一 mesh 权威数据。

3. 上下文与依赖

024 建立在 020 identity/registry/resolver/importer、021 image/texture、023 Material v2 与既有 Core math/RHI resource contracts 上。它为 cooker、runtime Asset Manager、Meshlet、streaming 和 BLAS derived data 提供稳定输入。Asset production 只依赖 Core 与 Asset 内部 contract；Renderer 可依赖 Asset 与 RHI；Backend 只理解 RHI，不解析 glTF，也不持有 Asset identity。

二、目标与边界

1. 业务与功能目标

引擎开发者向 scoped importer 提交 source identity、bytes、resolver 与 versioned import profile。成功时得到 identity-sorted 完整 package；失败时输出为空并返回稳定 diagnostic。调用方可将任意 FStaticMeshAsset 交给 FStaticMeshRealizer，成功后获得深拥有 RHI buffers、vertex layout、sections、bounds 与 source manifest 的 immutable snapshot。

2. 架构目标与定位

.gltf/.glb + resolver
        |
        v
Asset private: preflight -> cgltf -> decode -> normalize -> assemble
        |
        +--> FStaticMeshAsset / FStaticModelAsset / Material / Image / Texture
                                      |
                                      v
Renderer: validate -> pack -> allocate -> upload -> publish snapshot
                                      |
                                      v
RHI portable buffer/upload/indexed-draw contract
                                      |
                                      v
Vulkan native allocation, staging, submission and readback

Public Asset contract 只包含 typed CPU 数据、identity/version、dependency 与 metadata。cgltf、MikkTSpace、物理文件和 Vulkan 都留在 private/composition 边界。具体图形 API 没有进入 Asset，因此 DX12/Metal 可实现相同 RHI transfer contract。

3. 边界与非目标（约束）

  • 不导入 skin、animation、morph target、camera/light：它们需要独立 runtime 与 ECS 语义，留给 Skeletal/Scene tracks。
  • 不把 glTF scene 直接实例化为 ECS：Model Asset 是可复用描述，不应在 import 时产生 world side effect。
  • 不做 cooker、DDC、package 或 async manager：这些属于后续 025/026，当前 import 保持 request-scoped。
  • 不做 mesh optimization、LOD、meshlet 或 BLAS：它们是 canonical mesh 的 derived data，而非 source authority。
  • 不支持 Draco、EXT_meshopt_compression 与任意 required extension：缺少经过规划的 decoder 时必须 fail closed。
  • 不绑定 GPU vertex bytes 到 Asset schema：否则切换 backend/profile 会迫使资产身份与格式一起变化。

三、交互与产品设计

1. 用户使用路径

Resolve source and dependencies
  -> Import(request, outputs, diagnostics)
  -> validate complete package
  -> atomically register outputs
  -> Realize(mesh asset, device, profile)
  -> immutable render snapshot

Any import failure  -> outputs == empty
Any realize failure -> snapshot == null; temporary RHI resources released

调试时先运行 --suite asset-static-model 看 import identity/package，再运行 --suite asset-gltf-malformed 看 first-failure category，最后运行 --suite renderer-static-mesh 定位 validate/plan/allocate/upload/finalize 阶段。

2. 核心规则与状态机

Import: Preflight -> Parse -> Resolve -> Decode -> Normalize -> Assemble -> Publish
Realize: ValidateAsset -> Plan -> Allocate -> Upload -> Finalize -> Publish

Only Publish exposes a result. Earlier failure discards all request-owned state.

Import profile、source/dependency digest 与稳定结构键共同进入 version evidence。显式 extras.stonerAssetId 使用 key.* namespace；缺省身份使用 typed idx.* structural key；display name 永不参与 identity。一个 glTF scene 对应一个 Model，未被 scene 引用的 Mesh 仍然输出。

3. 失败模式与调试入口

  • GLB header/chunk 顺序、长度、padding 或 embedded NUL 错误在 preflight 阶段终止。
  • URI traversal、query/fragment、unsupported scheme、digest/type mismatch 在 dependency resolver 阶段终止。
  • 越界 accessor、非法 stride/sparse index、非有限 position、非 triangle mode 在 decode/validation 阶段终止。
  • scene cycle、multiple parent、重复 explicit key 与 dependency conflict 在 package validation 阶段原子回滚。
  • RHI allocation/upload 注入失败返回首个稳定 realization diagnostic，并证明无 request-owned live resource。

四、技术架构与关键决策

1. 技术栈与基础设施

C++20、传统 public/private header/source、SCons 4.10.1。cgltf 与 MikkTSpace 以私有 C/C99 translation unit 编译；fixture、generator 与 Python verifier 全部 checked in，CI 不在线下载测试数据。本地 macOS 使用 Apple Clang 21；三平台 strict Release、Linux sanitizer 与 Lavapipe native readback 由 GitHub Actions 承担。

2. 关键信息

(1) 模块对应关系

(2) 数据与资源流

glTF 右手 Y-up 数据通过 Engine.X=Gltf.Z、Engine.Y=-Gltf.X、Engine.Z=Gltf.Y 进入左手 Z-up、+X forward 空间。反射已经把 source CCW 映射到 engine clockwise，因此 index order 不再翻转；tangent w 只因 basis reflection 取反一次。Renderer 将 position/normal/tangent/UV 按 profile 打包，并通过 IRHIDevice::UploadBuffer 上传，section 记录完整 first index、index count 与 vertex offset。

(3) 诊断与可视化

Import diagnostic 记录稳定 Asset identity、source element key、category/code 与 reason，不记录地址和平台路径。Inspection 按 identity 排序输出 package、geometry、hierarchy、material 与 dependency 摘要。Determinism gate 对完整 payload、manifest 和 diagnostics 做 20 次比较；native report 额外记录上传 byte hash、section 与 indexed clockwise readback。

六、设计巧思与最佳实践

1. 当前业务场景与业务模型的最佳实践

  • 先 envelope 再 parser：损坏 GLB 在建立复杂 object graph 前被稳定拒绝。
  • checked arithmetic 先于 allocation：offset、stride、count 与 aggregate bytes 都先在 64-bit 范围验证。
  • basis reflection 与 node determinant 分离：前者是格式转换，后者是实例变换，混用会造成二次翻面。
  • Asset 与 realization 两段 transaction：CPU package 完整不代表 GPU upload 必然成功，两边都必须各自原子发布。
  • stable identity 不依赖 display name：编辑器重命名不会使软引用和未来 DDC key 失效。
  • valid-but-unsupported 单独分类：glTF Validator 通过不代表 Feature 024 scope 接受，诊断要区分格式损坏与能力缺失。

2. 优化方案与收益

已实现 bounded parser allocator、request-local dependency dedup、16/32-bit canonical index 保留、按需 tangent generation、单 mesh 双 buffer packing、immutable shared payload 与 deterministic ordering。收益主要是受控峰值、较少 RHI object、稳定 cache input 和并发只读安全。尚未实现的 meshoptimizer、LOD、meshlet、streaming 与 GPU residency 将以当前 canonical payload 作为 derived-data 输入，不必改变 source identity。

3. 已知限制与后续演进

当前 static-only、最多 UV0/UV1、核心 metallic-roughness、PNG/JPEG，且不支持压缩 mesh extension。025 将建立 manifest/DDC/cooker，026 加载与缓存 runtime payload，027 才从 cooked mesh 生成 meshlet；后续 Skeletal track 需基于研究重新决定 smooth/sharp normal、skin hierarchy 与 animation contracts。现有 corpus、identity golden、transaction tests 和 native byte hash 将成为这些演进的回归基线。

七、编程语言知识点

1. 标准库接口与用法

std::span 提供不拥有的 source/accessor byte view；std::shared_ptr<const T> 发布 immutable Asset payload；std::optional 表达 mesh ref、default scene 与可选 subresource；std::variant 承载 material typed value；std::async 与 future 验证八路独立 import；std::chrono 生成 performance report；std::from_chars 解析无 locale 的测试参数。

2. 语言特性与惯用法

RAII 管理 cgltf document、registration token、execution lease 与临时 RHI resource；移动语义把 request scratch 一次性交给 immutable output；enum class 对 policy/stage/result fail closed；[[nodiscard]] 强迫调用方处理 import/realization 结果；private helper class 隐藏第三方类型；checked helper 与 out parameter 避免异常跨层传播。

3. 平台相关与编译器行为

Private C translation units 隔离 Clang/GCC/MSVC warning；project C++ 在 strict mode 使用 -Werror//WX。Canonical identity、digest、float evidence 与 inspection 不依赖 locale、地址或物理路径。macOS sandbox 中 MoltenVK 可被探测但 Metal 不可用，因此仅接受 controlled unavailable；真实 native 由有图形能力的平台或 Linux Lavapipe 提供。

八、软件工程知识点

1. 设计模式与架构模式

IAssetResolver/IAssetImporter 是 Strategy；cgltf、Material mapper 与 Renderer realizer 是 Adapter；AssetId/version/profile 是 Value Object；import pipeline 类似 compiler front-end；package assembler 和 realization publish 是 Unit of Work；source manifest 是 provenance record；fixture verifier 与 native probe 是独立 Contract Test。

2. 工程原则与方法论

Dependency Inversion 保证 Asset 不认识 Renderer/RHI；Single Responsibility 把 container、accessor、geometry、hierarchy、material、identity 与 assembly 拆开；YAGNI 推迟 cooker/streaming；Design by Contract 验证每个 byte range、semantic、dependency 与 stage；defensive parsing 为本地不可信资产输入设置有限预算；deterministic design 让测试 evidence 未来可直接成为 derived-data key。

3. 测试策略与质量保障

Valid/invalid corpus 做 equivalence partitioning；exact-limit 与 first-above 做 boundary testing；mutation manifest 做 targeted negative testing；golden geometry/identity 防 silent semantic drift；failure injection 覆盖 transaction rollback；20 次重复与 8 路并发覆盖 determinism/ownership；ASan/UBSan/TSan 覆盖 parser 与共享状态；architecture scanner 防第三方/native type 穿透 public boundary。

九、渲染、引擎与图形 API 学习笔记

1. 本期核心概念拆解

  • Canonical mesh：引擎语义空间中的权威 CPU 几何，不是 glTF accessor view，也不是 GPU bytes。
  • Model vs Mesh：Mesh 拥有几何；Model 拥有 scene/node/local transform 并软引用 Mesh。
  • Tangent frame：normal、tangent.xyz 与 handedness w 共同重建 bitangent，reflection 必须只修正一次。
  • Section：打包 buffer 中一个 primitive 的 indexed draw 范围与 material identity。
  • Realization snapshot：某 Asset version/profile 在某 RHI device 上的 immutable GPU-ready 结果。
