2. 本期核心摘要

本阶段交付 Renderer 层 Render Graph Foundation：开发者可以声明 passes 与虚拟资源，编译出稳定 schedule、资源生命周期、aliasing 诊断与 transition plan，并通过 mock command context 执行。

3. 上下文与依赖

本功能依赖 Core 基础类型、RHI 公共概念和已完成的 Vulkan backend 回归测试，但 Renderer public API 不暴露后端头文件，也不要求 Application 层获取 RHI include path。

二、目标与边界

1. 业务与功能目标

  • 用 FRenderGraphBuilder 声明 graphics、compute、copy 和 side-effect passes。
  • 用稳定 handle 管理 transient、imported、exported 资源。
  • 编译得到 deterministic schedule、dependency edges、culling、lifetime、aliasing decisions 和 transition plan。
  • 执行时解析 transient resources，校验 imported resources，并 fail-fast 处理 pass failure。

2. 架构目标与定位

Application
    ↓ includes
Renderer public Render Graph API
    ↓ internal concepts
Renderer compiler / executor / diagnostics
    ↓ future backend-facing adapters
RHI contracts and backend implementations

3. 边界与非目标

本阶段不实现材料系统、shader permutation、具体 forward/deferred pass、scene graph、visible presentation、async compute overlap、多线程 compilation，也不真正复用 alias backing storage。

三、交互与产品设计

1. 用户使用路径

  1. 创建 FRenderGraph 并通过 CreateBuilder() 获得 builder。
  2. 声明资源、passes、资源访问和 graph outputs。
  3. 调用 Compile() 获取可检查 metadata。
  4. 调用 Dump() 查看文本化图结构。
  5. 调用 Execute() 注入 imported resource bindings 与 command context。

2. 核心规则与状态机

Draft -> Compile Success -> Compiled -> Execute Success -> Executed
Draft -> Compile Failure -> Failed
Compiled -> Execute Failure -> Failed
Compiled/Failed/Executed -> Invalidate -> Invalidated
Any terminal state -> Reset -> Draft

四、技术架构与关键决策

1. 技术栈与基础设施

C++20、传统 header/source 分离、SCons 4.10.1、现有 Core 容器与类型别名。测试仍挂入单一 StonerTest 可执行文件。

2. 关键信息

模块职责
FRenderGraph拥有 declaration、compiled graph、diagnostics、状态切换与 reset/invalidate。
FRenderGraphBuilder提供声明入口，保持 handle 属主校验。
FRenderGraphCompiler构建 dependency edges、稳定拓扑排序、culling、lifetimes、alias decisions、transition plan。
FRenderGraphExecutor解析 transient/imported resources，emit transitions，按 schedule 调用 callbacks。
FRenderGraphDiagnosticLog存储并格式化 deterministic diagnostics。

3. 架构决策记录 (ADR)

ADR-1：Renderer public API 不直接 include RHI 头。

初版资源描述尝试复用 RHI desc，但 Application 层只允许 include Renderer/Core，构建立即暴露边界问题。最终改为 Renderer 自有抽象字段，让 RHI-facing 行为留在未来适配层或 Renderer private 实现中。

ADR-2：aliasing 只报告 eligibility。

编译器报告 compatible non-overlapping transient resources，但 executor 仍分配独立 backing id，降低 foundation 阶段风险。

ADR-3：transition plan 必须可检查且执行复用同一计划。

执行器逐条 emit compiled transition records，测试直接比较 emitted transitions 与 compiled plan 数量，保证 inspect 与 runtime 行为一致。

六、设计巧思与最佳实践

6.1 当前业务场景与业务模型的最佳实践

Render Graph 把“工作声明”和“执行策略”分开：pass 只声明资源访问与 callback，compiler 负责 schedule 与 metadata，executor 负责 runtime 校验。这让后续 forward/deferred/material 系统可以复用同一调度基础。

6.2 优化方案与收益

  • 稳定拓扑排序让 debug dump 和测试具备 byte-stable 行为。
  • 输出驱动 culling 避免无用 pass 进入 executable schedule。
  • lifetime 和 aliasing metadata 先行，为未来真实 transient allocator 打底。

七、编程语言知识点

1. 标准库接口与用法

  • std::vector 通过 Core::TArray 用于稳定顺序集合。
  • std::function 承载 pass callback。
  • std::ostringstream 生成 deterministic text dump。
  • std::atomic 生成 graph instance id，区分跨图 handles。
  • <chrono> 用于 SC-001 代表性流程耗时测试。

2. 语言特性与惯用法

  • 强类型 enum 表达 result、state、access、transition reason。
  • friend class 限制 builder/compiler/executor 对 graph 内部状态的访问。
  • [[nodiscard]] 用于提醒调用方处理关键 result 和 handles。

3. 平台相关与编译器行为

实现本身无平台分支。macOS 构建过程中出现的 confstr() 临时目录 warning 来自 toolchain 环境，不影响项目编译或测试结果。

八、软件工程知识点

1. 设计模式与架构模式

  • Builder：FRenderGraphBuilder 负责声明期 API。
  • Compiler pipeline：validation、schedule、lifetime、transition planning 分步产出 metadata。
  • Facade：FRenderGraph 对外提供 compile/execute/reset/dump 的简洁入口。

2. 工程原则与方法论

  • 边界优先：Renderer public API 不泄漏后端 API 或 RHI include path 假设。
  • YAGNI：aliasing 先诊断不复用，避免 foundation 阶段过度优化。
  • 契约式设计：execution 前置条件、imported resource、invalidated graph 都显式失败。

3. 测试策略与质量保障

测试覆盖成功路径、负面路径、重复确定性、执行失败、reset/invalidation、debug dump 和后端边界。所有测试并入既有 StonerTest，确保新增 Renderer 能与 Core/RHI/Vulkan 回归一起验证。
